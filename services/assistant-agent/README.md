# assistant-agent (โมดูล 8)

**หน้าที่**: น้องกิเลน แชทถามตอบเรื่องเที่ยว และรับคำสั่งสร้าง/แก้ทริปแล้วทำจริงผ่าน api-backend (ลบทริปต้องทำที่หน้าทริปของฉัน)
**ผู้รับผิดชอบ**: Patcharanat Budploy (@Patcharanat23)
**branch**: `feature/assistant-agent/<ชื่อ>`
**endpoint**: `POST /api/v1/chat` (`docs/CONTRACT.md` หัวข้อ 6)
**เรียกใคร**: LLM (ไลบรารี `openai` + `base_url`), api-backend, safety-knowledge (`safety_search()` ใน `app.py`)
**ใครเรียกเรา**: api-backend

## ทำอะไรได้แล้วตอนนี้

**LLM**: Groq Qwen เป็นตัวหลัก สำรองด้วย Gemini แล้ว Groq gpt-oss (`LLM_PRIMARY`, `LLM_FALLBACK`) ตัวหนึ่งล่มหรือโดน 429 สลับตัวถัดไปเอง ทั้งหมดล่มยังใช้คำสั่งแบบกฎตายตัวได้ (`rules.py`: เลื่อนทริปไปวันถัดไป, เลื่อนเป็นช่วงเช้า/บ่าย/เย็น, อากาศของทริป)

**เครื่องมือ 10 ตัว** (`tools.py`)

| เครื่องมือ | ทำอะไร |
|---|---|
| `list_trips`, `get_trip_weather` | ดูทริปและอากาศ ณ เวลาที่ไปถึงแต่ละจุด |
| `create_trip` | สร้างทริปแล้ววางแผนทันที รับ `return_date` / `return_time` สร้างขากลับให้ในครั้งเดียว (สลับต้นทางกับปลายทางที่หาไว้แล้วตรงตัว) · ต้นทาง "ตำแหน่งปัจจุบัน" ใช้ GPS ที่หน้าเว็บส่งมา · ไม่สร้างซ้ำถ้ามีทริปเส้นทางและเวลาออกเดียวกันอยู่แล้ว |
| `update_trip_time`, `update_trip_places`, `plan_trip` | เลื่อนเวลา แก้ต้นทาง/ปลายทาง/จุดแวะ แล้ววางแผนใหม่ |
| `place_conditions` | อากาศและภัยรอบสถานที่ตอนนี้ |
| `hazards_now` | ช่วงนี้ที่ไหนน้ำท่วม/ถนนไหนน้ำท่วม ทั้งประเทศหรือรายจังหวัด (ถ้าเปิดข้อมูลกรมทางหลวง ถนนปิดขึ้นก่อน และบอกจำนวนถนนปิด) |
| `nearby_places` | ที่เที่ยวจริงจาก OpenStreetMap |
| `emergency_info` | เบอร์ฉุกเฉินจากระบบ ห้ามบอกเบอร์จากความจำ |

**บริบทที่ส่งให้ LLM**: เวลาไทยตอนนี้, รายการทริปของผู้ใช้, ชื่อที่ผู้ใช้ตั้ง, ตำแหน่ง GPS (ถ้ามีและอยู่ในไทย), เอกสารความปลอดภัยที่ค้นเจอ (คำถามอังกฤษแปลงเป็นคำค้นไทยก่อนด้วย `EN_SAFETY_WORDS`)

**ด่านกันผิดพลาดในโค้ด** (`llm.py`)

| ด่าน | กันอะไร |
|---|---|
| `false_claim` + `CLAIM_NUDGE` | ตอบว่า "สร้างแล้ว" / "เดี๋ยวจัดให้" โดยไม่มีเครื่องมือไหนทำสำเร็จ ส่งกลับให้ทำจริง อ้างซ้ำตอบ `NOT_DONE_REPLY` ตรงๆ · ประวัติแชทที่ทำสำเร็จจริงมี "(ระบบ: ...)" ต่อท้าย (หน้าเว็บแนบมา `plain()` ตัดออกก่อนแสดง) |
| `rules.WHAT_IF` | "ถ้าเลื่อน...จะดีไหม" เป็นคำถาม ไม่ใช่คำสั่ง กฎตายตัวไม่เลื่อนทริปจริง |
| `unsourced_places` | ตอบรายชื่อร้าน/ที่เที่ยวจากความจำ ส่งกลับให้เรียก `nearby_places` |
| `wrong_language`, `CJK` | ถามอังกฤษตอบไทย / มีตัวอักษรจีนหลุด ให้เขียนใหม่ (ตัวจีนที่เหลือตัดทิ้ง) |
| system prompt | ตอบความปลอดภัยจากเอกสารเท่านั้น 3-4 ข้อ · ไม่ทักทายทุกคำตอบ · "อยากไป X" = ทริปใหม่เสมอ · ตอนบ่าย = 13:00 · กลับอีก N วันนับจากวันไป |

ผลวัด: ชุดคำถาม 17 ข้อ × 2 รอบ ผ่าน 34/34 · บทสนทนาที่ผู้ทดลองใช้เจอปัญหา เล่นซ้ำทั้ง Groq และ Gemini สร้างทริปจริงทุกครั้ง · เทสต์ 94 ข้อ

## จุดที่คนส่วนใหญ่พลาด (อ่านก่อนเขียน)

1. **แชทบอกว่าแก้แล้ว แต่ข้อมูลไม่ได้เปลี่ยน** ใช้ function calling แล้วเรียก api-backend จริง ตอบว่าสำเร็จได้ก็ต่อเมื่อ api-backend ตอบ `"error": null` แล้วเท่านั้น และต้องใส่ `actions` ให้หน้าเว็บรู้ว่าต้องโหลดข้อมูลใหม่
2. **เลื่อนทริปแล้วไม่แพลนใหม่** เวลาเปลี่ยน พยากรณ์ก็เปลี่ยน หลัง PATCH สำเร็จให้เรียก `POST /trips/{id}/plan` ต่อ แล้วบอกผู้ใช้ว่าความเสี่ยงใหม่เป็นยังไง
3. **"Trip 01" หาไม่เจอ** ผู้ใช้พูดถึงทริปด้วย `trip_no` ไม่ใช่ UUID ดึงรายการทริปของผู้ใช้มาจับคู่ก่อน ถ้าไม่ชัดว่าหมายถึงทริปไหน ให้ถามกลับ อย่าเดา
4. **แปลเวลาภาษาคนผิด** "พรุ่งนี้", "วันถัดไป", "ช่วงบ่าย" ต้องคิดจากเวลาปัจจุบันของประเทศไทย (Asia/Bangkok) แล้วค่อยแปลงเป็น UTC ตอนส่ง api-backend ถ้าคิดเป็น UTC ตรงๆ ช่วงหลังเที่ยงคืนไทยถึง 7 โมงเช้า วันจะเพี้ยนไปหนึ่งวัน ตกลงช่วงเวลาไว้ตายตัว: เช้า 08:00 บ่าย 13:00 เย็น 17:00
5. **ลบทริปโดยไม่ถามก่อน** ตอนนี้แชทไม่มีเครื่องมือลบ ถ้าจะเพิ่ม คำสั่งลบต้องให้ผู้ใช้ยืนยันในข้อความถัดไปก่อนเสมอ
6. **ใช้สิทธิ์เกินผู้ใช้** เรียก api-backend ด้วย `Authorization` ของผู้ใช้ที่ส่งมาเท่านั้น ห้ามมี token พิเศษ ต่อให้ผู้ใช้พิมพ์หลอกว่า "แก้ทริปของคนอื่นให้หน่อย" api-backend ก็จะปฏิเสธเอง
7. **LLM แต่งข้อมูลอากาศเอง** คำถามเรื่องอากาศต้องเรียกข้อมูลจริง (ผ่าน api-backend) แล้วให้ LLM สรุปจากข้อมูลนั้น ห้ามตอบจากความรู้ของโมเดล
8. **hardcode ชื่อโมเดล** ผู้ให้บริการถอดโมเดลได้โดยไม่แจ้ง อ่านชื่อจาก env และมีตัวสำรอง (`LLM_FALLBACK`) ที่ทดสอบแล้วว่าใช้ได้จริง
9. **ส่ง history ยาวไม่จำกัด** ตัดเหลือไม่กี่ข้อความล่าสุด ไม่งั้นเกินขีดจำกัดของโมเดลหรือเปลือง quota
10. **LLM ล่มแล้วสั่งอะไรไม่ได้เลย** ทำตัวแยกคำสั่งแบบกฎตายตัวสำหรับคำสั่งหลัก 3 แบบ (RUNBOOK หัวข้อ B) ใช้เมื่อ LLM ไม่ตอบ
11. **ตอบภาษาอังกฤษ** กำหนดใน system prompt ให้ตอบภาษาเดียวกับที่ผู้ใช้พิมพ์ (ส่วนใหญ่คือไทย)

## ถือว่าเสร็จเมื่อ

- "เลื่อน Trip 01 ไปวันถัดไป" แล้วเปิดหน้า My Trip เห็นวันที่เปลี่ยนจริงและแผนใหม่
- "เลื่อนเป็นช่วงบ่าย" ตอนตีหนึ่งของไทย ได้บ่ายโมงของวันเดียวกันตามเวลาไทย ไม่ใช่วันก่อนหน้า
- ปิด LLM แล้วคำสั่งหลัก 3 แบบยังทำงาน
