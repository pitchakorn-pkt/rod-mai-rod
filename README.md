- นำเสนอ: พุธ 7 ตุลาคม 2569

### น้องกิเลนทำอะไรได้ (ตัวอย่างคำสั่ง)

| พิมพ์ | ผล |
|---|---|
| "สร้างทริปไปหัวหินเสาร์นี้ 8 โมง กลับวันอาทิตย์ 5 โมงเย็น" | สร้าง 2 ทริป (ขาไป + ขากลับ) ต้นทางจาก GPS ขากลับจบที่จุดเริ่มต้นเดิม แล้ววางแผนให้ทันที |
| "เลื่อน Trip 01 ไปวันถัดไป" / "เลื่อน Trip 01 เป็นช่วงบ่าย" | เลื่อนทริปจริงและวางแผนใหม่ (ใช้ได้แม้ LLM ล่ม) |
| "Trip 01 อากาศเป็นยังไง" | อากาศ ณ เวลาที่ไปถึงแต่ละจุดของทริป |
| "ช่วงนี้ที่ไหนน้ำท่วมบ้าง" / "ถนนไหนปิด" | สรุปจาก GISTDA + กรมทางหลวง ทั้งประเทศหรือรายจังหวัด |
| "น้ำท่วมระหว่างทางต้องทำยังไง" / "รถดับกลางน้ำ" | ตอบจากเอกสารความปลอดภัยเท่านั้น พร้อมที่มา |
| "เชียงใหม่มีคาเฟ่แนะนำไหม" | ที่เที่ยวจริงจาก OpenStreetMap ไม่แต่งชื่อเอง |

กันความผิดพลาดไว้ในโค้ด (ไม่พึ่งแค่ prompt):
- บอกว่า "สร้างแล้ว" ได้เฉพาะเมื่อสร้างสำเร็จจริง ถ้าโมเดลอ้างโดยไม่ได้ทำ ระบบส่งกลับให้ทำจริงหรือบอกผู้ใช้ตรงๆ
- ไม่สร้างทริปซ้ำ (เส้นทางและเวลาออกเดียวกัน) · คำถามแบบ "ถ้าเลื่อน...จะดีไหม" ไม่เลื่อนทริปจริง
- ระดับความเสี่ยงมาจากกฎเท่านั้น LLM ไม่ได้ตัดสิน · ลบทริปผ่านแชทไม่ได้

### คิดความเสี่ยงอย่างไร

- ใช้ **พยากรณ์ ณ เวลาที่รถไปถึงแต่ละจุด** (จุดตัวอย่างทุกประมาณ 20 กม. + ทุกจุดแวะ) ไม่ใช่อากาศตอนกดวางแผน
- เกณฑ์: ฝน < 10 / 10-35 / > 35 มม./ชม. · ลม < 40 / 40-61 / > 61 กม./ชม. · หมุดภัยในรัศมี 20 กม. · **ถนนน้ำท่วมจากดาวเทียมหรือถนนปิดที่เส้นทางผ่านจริง (ห่างไม่เกิน 0.5 กม.)**
- ระดับของเส้นทาง = จุดที่แย่ที่สุด แล้วตัดสินคำแนะนำ `NORMAL` / `REROUTE` (เส้นอื่นปลอดภัยกว่าและช้ากว่าไม่เกิน 50%) / `DELAY` (ออกช้า 3 หรือ 6 ชม. แล้วดีขึ้น) / `AVOID`
- ข้อมูลไม่ครบไม่เดาว่า "ต่ำ" แต่บอกว่าไม่มีข้อมูล

รายละเอียดเกณฑ์ทั้งหมดอยู่ใน [`docs/CONTRACT.md`](docs/CONTRACT.md) หัวข้อ 4

## 2. โครงสร้างระบบ

บริการ Python (FastAPI) 6 ตัว + หน้าเว็บ Next.js + Postgres หน้าเว็บคุยกับ api-backend ที่เดียว

```
browser ──> web (Next.js :3000) ──/api/v1/*──> api-backend (:8001) ──> Postgres
                                                  │
              ┌───────────────────┬───────────────┼────────────────────┬──────────────────┐
              v                   v               v                    v                  v
     routing-engine (:8002)  weather-disaster  assistant-agent (:8005)  safety-knowledge   Photon / Overpass
        │  OSRM                (:8003)            │  Groq / Gemini        (:8006)          (ค้นสถานที่ / ที่เที่ยว)
        v                       ^                 └─> api-backend (แก้ทริปด้วยสิทธิ์ผู้ใช้)
     risk-decision (:8004) ─────┘                 └─> safety-knowledge (เอกสารความปลอดภัย)
```

| service | พอร์ต | หน้าที่ |
|---|---|---|
| `apps/web` | 3000 | หน้าเว็บทั้งหมด ส่งต่อ `/api/v1/*` ไป api-backend |
| `services/api-backend` | 8001 | login (อีเมล + Google), JWT, โปรไฟล์, ทริปใน Postgres, rate limit, ส่งต่องานไปบริการอื่น, ค้นสถานที่, ที่เที่ยวรอบตัว |
| `services/routing-engine` | 8002 | หาเส้นทางจาก OSRM (หลายเส้น), เวลาถึงแต่ละจุด, ส่งให้ risk-decision ประเมิน, ประกอบแผนทริป |
| `services/weather-disaster` | 8003 | พยากรณ์รายชั่วโมง (Open-Meteo), หมุดภัย (GDACS, USGS, GISTDA, กรมทางหลวง, ประเมินดินถล่มเอง), อากาศรอบตัว |
| `services/risk-decision` | 8004 | ตัดสินระดับความเสี่ยงและคำแนะนำด้วยกฎ |
| `services/assistant-agent` | 8005 | น้องกิเลน: LLM + function calling 10 เครื่องมือ + คำสั่งแบบกฎตายตัวเมื่อ LLM ล่ม |
| `services/safety-knowledge` | 8006 | คลังเอกสารความปลอดภัย (RAG) 10 ไฟล์ + เบอร์ฉุกเฉินตามชนิดภัย |

รูปแบบข้อมูลกลาง (พิกัด `{lat, lng}`, เวลา UTC, `{data, error}`), endpoint ทุกเส้น และ timeout อยู่ใน [`docs/CONTRACT.md`](docs/CONTRACT.md)

## 3. แหล่งข้อมูลและ API ภายนอก

| แหล่ง | ใช้ทำอะไร | ต้องมี key | ข้อจำกัดที่ควรรู้ |
|---|---|---|---|
| OSRM (router.project-osrm.org) | เส้นทาง | ไม่ต้อง | เซิร์ฟเวอร์สาธิตสาธารณะ ไม่รับประกัน · มี cache |
| Open-Meteo | พยากรณ์รายชั่วโมง, อากาศรอบตัว | ไม่ต้อง | 10,000 ครั้ง/วันต่อ IP · มี cache |
| GDACS | ภัยพิบัติ (น้ำท่วม พายุ) | ไม่ต้อง | ข้อมูลทั้งโลก กรองเฉพาะไทย |
| USGS | แผ่นดินไหว | ไม่ต้อง | |
| GISTDA | พื้นที่น้ำท่วมจากดาวเทียม 3 วัน (ว่างใช้ 7 วัน) รวมเป็นรายตำบล | `GISTDA_API_KEY` (สมัครฟรี) | ดึงเบื้องหลังทุก 30 นาที ไม่มี key = ปิดชั้นนี้ |
| HDMS กรมทางหลวง | ถนนปิด/น้ำท่วมทางหลวง ระดับน้ำ ทางเลี่ยง | ไม่ต้อง | เป็น API ภายในของเว็บ HDMS ไม่ใช่ open data ทางการ · ดึงทุก 15 นาที ล่มแล้วใช้ข้อมูลล่าสุด · ปิดได้ด้วย `DOH_HDMS=false` |
| Photon (komoot) | ค้นชื่อสถานที่ (รองรับคำย่อ เช่น มทร, รพ) | ไม่ต้อง | |
| Overpass (OpenStreetMap) | ที่เที่ยวรอบตัว | ไม่ต้อง | ช้าบางเวลา มี cache รายวัน + สำรองด้วย Photon |
| Esri World Street Map | แผนที่พื้นหลัง (ชื่อภาษาอังกฤษทั้งแผนที่) | ไม่ต้อง | |
| Groq (Qwen) | LLM ตัวหลักของน้องกิเลน | `GROQ_API_KEY` | ฟรี 1,000 ครั้ง/วัน และ 8,000 token/นาที ชนแล้วสลับตัวสำรองเอง |
| Google Gemini | LLM สำรองตัวที่ 1 | `GEMINI_API_KEY` | |
| Groq (gpt-oss) | LLM สำรองตัวที่ 2 | `GROQ2_API_KEY` | ใช้ key เดียวกับ Groq ได้ (โควตาแยกตามโมเดล) |

## 4. รันบนเครื่อง

ต้องมี Docker Desktop และแรมว่างประมาณ 2 GB

```bash
make up        # สร้าง .env จาก .env.example ถ้ายังไม่มี แล้วรันทั้งระบบ
make health    # ทุก service ต้องตอบ ok
make smoke     # ไล่เส้นหลัก login > สร้างทริป > วางแผน > แชท ต้องผ่านทุกข้อ
```

เปิดเว็บที่ http://localhost:3000 · บัญชีทดลอง `demo@example.com` / `demo1234` (สร้างให้อัตโนมัติ) หรือสมัครใหม่

ก่อนรันครั้งแรกให้ใส่ key ใน `.env` (หัวข้อ 5) ไม่ใส่ก็รันได้ แต่แชทใช้ได้แค่คำสั่งแบบกฎตายตัวและไม่มีชั้นน้ำท่วมจากดาวเทียม

**ไม่มี `make` (Windows ส่วนใหญ่)**

| make | คำสั่งที่ใช้แทน |
|---|---|
| `make up` | `copy .env.example .env` (ครั้งแรกครั้งเดียว) แล้ว `docker compose up --build -d` |
| `make down` | `docker compose down` (ข้อมูลยังอยู่) |
| `make reset` | `docker compose down -v` (ลบข้อมูลในฐานข้อมูลด้วย) |
| `make logs` | `docker compose logs -f --tail=100` |
| `make health` | `curl http://localhost:8001/health` (เปลี่ยนพอร์ตเป็น 3000, 8002 ถึง 8006 ทีละตัว) |
| `make smoke` | `sh scripts/smoke.sh http://localhost:8001` (Git Bash) |

รันหน้าเว็บอย่างเดียวนอก Docker ดู [`apps/web/README.md`](apps/web/README.md) · รัน service เดียว ดู README ในโฟลเดอร์ของ service นั้น

## 5. ตั้งค่า `.env`

คัดลอก `.env.example` เป็น `.env` แล้วเติมค่า **ห้าม commit `.env`** (อยู่ใน `.gitignore` แล้ว) ส่ง key ให้คนอื่นทางแชทส่วนตัวเท่านั้น

| ตัวแปร | ต้องใส่ไหม | ใช้ทำอะไร |
|---|---|---|
| `GROQ_API_KEY`, `GEMINI_API_KEY`, `GROQ2_API_KEY` | ควรใส่ | LLM ของน้องกิเลน (ลำดับตาม `LLM_PRIMARY` แล้ว `LLM_FALLBACK`) |
| `GISTDA_API_KEY` | ควรใส่ | ชั้นน้ำท่วมจากดาวเทียม + ความเสี่ยงจากถนนน้ำท่วม |
| `GOOGLE_CLIENT_ID` | ถ้าจะเปิดปุ่ม Google | ว่าง = หน้า login ไม่แสดงปุ่ม (อ่านตอนรัน ไม่ต้อง build เว็บใหม่) |
| `JWT_SECRET`, `POSTGRES_PASSWORD` (+ รหัสใน `DATABASE_URL`) | **เปลี่ยนก่อนเปิดให้คนนอกใช้** | ค่าใน `.env.example` เป็นค่าตัวอย่าง |
| `DEMO_MODE` | ไม่ต้อง (ค่าตั้งต้น `false`) | `true` = ใช้ข้อมูลที่บันทึกไว้ |
| `DOH_HDMS` | ไม่ต้อง (ค่าตั้งต้นเปิด) | `false` = ปิดข้อมูลถนนปิดของกรมทางหลวง |
| `LONGDO_MAP_API_KEY`, `OPENROUTESERVICE_API_KEY`, `THAIWATER_API_KEY`, `TMD_API_KEY`, `OPENAI_*` | ไม่ต้อง | เตรียมไว้ตั้งแต่ช่วงวางแผน โค้ดปัจจุบันไม่ได้ใช้ ปล่อยว่างได้ |

ที่อยู่ของแต่ละ service (`*_URL`) และค่าโมเดล LLM ใช้ตามใน `.env.example` ได้เลย

## 6. ขึ้นเซิร์ฟเวอร์

### เซิร์ฟเวอร์ทั่วไป (ที่ใช้อยู่ตอนนี้)

เว็บจริงรันด้วย `docker compose` บนเซิร์ฟเวอร์ที่มีแรมอย่างน้อย 2 GB (ระบบใช้แรมราว 650 MB ตอนไม่มีคนใช้)

```bash
git clone https://github.com/pitchakorn-pkt/rod-mai-rod.git && cd rod-mai-rod
# วาง .env ที่โฟลเดอร์นี้ (ระดับเดียวกับ docker-compose.yml)
docker compose up -d --build
```

อัปเดตเวอร์ชัน: `git pull` แล้ว `docker compose up -d --build` (ข้อมูลในฐานข้อมูลยังอยู่) ถ้ามีตัวแปรใหม่ใน `.env.example` ให้เพิ่มใน `.env` ก่อน

ถ้าจะเปิด login ด้วย Google ที่โดเมนใหม่ ต้องเพิ่มโดเมนนั้นใน Google Cloud > Google Auth Platform > Clients > Authorized JavaScript origins

### Render

มี `render.yaml` + `deploy/render/` รวมทุกบริการเป็น container เดียว ต้องใช้แพ็กเกจ **Standard (2 GB)** ขึ้นไป (แพ็กเกจ 512 MB แรมไม่พอ) วิธีทำอยู่ใน [`deploy/render/README.md`](deploy/render/README.md)

## 9. Git flow

```
feature/<module-slug>/<ชื่อ> หรือ fix/<เรื่อง>  ──PR──>  dev  ──PR──>  main  ──>  deploy
```

- ทำงานใน branch ของตัวเอง แตกจาก `dev` · ห้าม push ตรงเข้า `dev` หรือ `main` (ruleset บล็อกไว้ พร้อมห้ามลบ branch และห้าม force push)
- PR จะ merge ได้เมื่อ CI ผ่าน (pytest 6 service + smoke) · merge แบบ "Create a merge commit" อย่างเดียว เก็บ commit ของทุกคนไว้เป็นหลักฐาน
- commit: `<type>(<module-slug>): <ทำอะไร>` เช่น `fix(assistant-agent): ...` type คือ `feat` `fix` `test` `docs` `refactor` `chore`
- ตอนเปิด PR ช่อง base เริ่มเป็น `main` ต้องเปลี่ยนเป็น `dev` เอง
- `git add` เฉพาะไฟล์ที่ตั้งใจ ห้าม commit `.env` หรือ key · merge แล้วพังให้ `git revert -m 1 <merge commit>` ห้าม force push

รายละเอียดอยู่ใน [`docs/CONTRACT.md`](docs/CONTRACT.md) หัวข้อ 11 · แจ้งเตือนรีวิวเข้า Discord ตาม [`docs/DISCORD_SETUP.md`](docs/DISCORD_SETUP.md)

## 11. ข้อจำกัดที่รู้แล้ว

- **OSRM สาธารณะ** เป็นเซิร์ฟเวอร์สาธิต ถ้าล่มจะวางแผนเส้นทางไม่ได้ชั่วคราว
- **HDMS กรมทางหลวง** ไม่ใช่ API ทางการ ถ้าเปลี่ยนรูปแบบ ระบบจะใช้ข้อมูลล่าสุดที่มีและข้ามไปเงียบๆ
- **Groq ฟรี 8,000 token/นาที** หลายคนแชทพร้อมกันจะสลับไป Gemini เอง คำตอบอาจช้าลง
- **rate limit** login 10 ครั้ง/นาทีต่อ IP (ทั้งห้องใช้ wifi เดียวกันจะนับรวม) แชท 10 ข้อความ/นาทีต่อคน
- **ไม่อนุญาตตำแหน่ง** แล้วไม่บอกต้นทางในแชท โมเดลอาจใช้กรุงเทพเป็นต้นทาง (คำตอบแสดงเส้นทางชัด แก้ได้)
- **จอ 1280×800** หน้าทริปที่มี 2 เส้นทางให้เลือก แผนที่ย่อจะเตี้ย
- **ประวัติแชท** เก็บในเบราว์เซอร์ ไม่ซิงก์ข้ามเครื่อง · **ลบบัญชี** ยังไม่มีปุ่ม ต้องขอผ่านอีเมลในหน้า `/privacy`
